# Architecture decisions

Short records of decisions made; add new ones at the bottom with a date.

## 001 — Modular monolith (2026-10-17)

One NestJS API organised by domain module (auth, cycles, estimates, readiness, content, reminders,
subscriptions, privacy, admin). No microservices until a module has a concrete scaling or isolation
need. Web, admin and mobile all call the same `/v1` API.

## 002 — Monorepo with pnpm workspaces + Turborepo (2026-10-17)

Apps are generated by their official CLIs (create-next-app, @nestjs/cli, create-expo-app) and kept
as separate workspace packages. Versions at setup: Next.js 16.4, NestJS 12.0, Expo SDK 58 /
React Native 0.88, Prisma 7.10, Turbo 2.11, Node 22.17, pnpm 11.17. The lockfile pins exact versions.

Shared packages compile to `dist/` (ESM, `nodenext`) so the ESM NestJS build and Metro can both
consume them. Run `pnpm build` before typechecking apps.

## 003 — Prisma 7 with the pg driver adapter (2026-10-17)

Prisma 7 requires a driver adapter; we use `@prisma/adapter-pg`. The client is generated into
`apps/api/src/generated/prisma` (git-ignored, regenerated on install/build). Connection settings
live in `apps/api/prisma.config.ts`.

Constraints Prisma cannot model (single-owner CHECKs, period range CHECK, no-overlap EXCLUDE
constraints, one-published-article partial index) are appended by hand to migrations. CI fails if
the schema and migrations drift.

## 004 — Better Auth for identity (2026-10-17)

Self-hosted Better Auth (TypeScript, Prisma adapter) rather than a hosted identity provider, so
identity records for a health-adjacent product stay in our own database. Its two-factor plugin
covers admin MFA. The auth tables (`users`, `auth_sessions`, `auth_accounts`,
`auth_verifications`) are already in the schema; on Day 2 run `npx @better-auth/cli generate`
and reconcile, configure UUID id generation, and map model/field names to the snake_case tables.

## 005 — Anonymous-first identity (2026-10-17)

Anonymous installs get a random secret held in platform-secure storage; the server stores only
its hash (`anonymous_sessions.credential_hash`). Linking to an account is an explicit,
authenticated migration. Every user-owned row has exactly one owner, enforced in the database.

## 006 — Errors, versioning and validation (2026-10-17)

- URI versioning: every route is `/v1/...`.
- `ValidationPipe` with `whitelist` + `forbidNonWhitelisted`: unknown fields are rejected.
- All errors use the `ApiError` shape from `@preconception/contracts` with a `requestId` that matches
  the `x-request-id` response header. 5xx responses are generic; logs record method, route
  pattern, error class and request id only — never request bodies.
- Global rate limit 120 req/min per IP; tighter limits per route for auth and exports.

## 007 — Product API conventions (2026-10-18)

- **Default deny.** A global guard requires an owner (registered user or anonymous session) on
  every route; routes opt out with `@Public()` / `@OptionalAuth()`. An e2e sweep fails if any
  non-public route answers without credentials.
- **Anonymous credential:** `Authorization: Anonymous <secret>` (43-char base64url, SHA-256
  hash stored). Retention slides by `ANONYMOUS_SESSION_TTL_DAYS`, written at most once a day.
- **Ownership** is applied in every query; another owner's id is a 404, never a 403.
- **Consent gate:** cycles, daily logs and task progress can be written only while
  `health_data_processing` is granted (403 `CONSENT_REQUIRED`). Withdrawal blocks new writes;
  existing data stays until the person deletes it.
- **Linking** anonymous data into an account is refused (409) if the account already holds
  health data. Merging two cycle histories silently could corrupt both.
- **Deletion** is immediate and irreversible; job and audit rows survive with `user_id` NULL.
  Staff accounts must be deprovisioned first so review trails stay intact.
- **Content:** draft → in review → approved → published; reviewers cannot approve their own
  articles; publishing archives the previous version; tasks need a clinical reviewer to publish
  and return to draft when edited.
- **Better Auth surface** is reduced to what is configured (`DISABLED_AUTH_PATHS`): no OAuth,
  email flows, OTP, or its own `delete-user` (it would bypass the audited deletion).
- **Estimates** (`calendar-average@1`): mean of up to 6 recent cycle lengths (15–90 days),
  window ± max(2, ⌈sd⌉) capped at 10, confidence never above "moderate", limitations always
  returned. No ovulation or fertility estimates.
- **Validation errors** carry structured `details[{path, message}]` with dotted paths.
- **Errors from the database** are mapped (409/400/404) without echoing Postgres messages,
  which quote row values such as cycle dates.

## Known exceptions

- `pnpm audit` ignores GHSA-86w9-cpqp-85rv (node-forge) and GHSA-vfj7-8cjw-p6xm (braces). Both are
  reached only through Expo/Metro build tooling, and no patched release existed on 2026-10-17.
  Reasons are recorded in `pnpm-workspace.yaml`; remove them once fixes ship.
- One moderate advisory (uuid via `xcode`, Expo CLI) is below the CI threshold and left in place.
- Better Auth routes (`/v1/auth/*`) return Better Auth's own error format, not `ApiError`.
