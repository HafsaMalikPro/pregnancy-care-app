# Pregnancy Care: web frontend

Next.js 16 (App Router) + TypeScript + Tailwind CSS 4 + Lucide icons. Talks to the NestJS API in the
`backend` repo over HTTP and holds no business logic of its own. Due dates, week, trimester,
milestones, consent and premium access all come from the API.

## Run locally

```sh
# 1. Start the backend first (see ../backend/README.md): Postgres + API on :4000
# 2. Then:
cp .env.example .env.local
pnpm install
pnpm dev                        # http://localhost:3000
```

| Variable | Purpose |
| --- | --- |
| `NEXT_PUBLIC_API_URL` | Base URL of the API. Must be listed in the API's `CORS_ORIGINS`. Public, not a secret. |
| `NEXT_PUBLIC_SITE_URL` | This site's public origin, used for canonical URLs, the sitemap and social cards. |
| `NEXT_PUBLIC_SUPPORT_EMAIL` | Optional. Shown on `/contact`. |

No server-side secrets are used. Public pages read published content from the API on the
server without cookies, so cached HTML never contains personal data.

## Checks and tests

```sh
pnpm lint && pnpm typecheck && pnpm test && pnpm build
```

`pnpm test` runs the Vitest unit tests (`src/**/*.test.ts`): due-date preview and
validation, sign-up validation, and API error handling.

`pnpm test:e2e` runs the Playwright suite in `e2e/` against a running site and API:

```sh
# API with the per-IP rate limit off, since the suite signs up many accounts:
(cd ../backend/apps/api && RATE_LIMIT_ENABLED=false node dist/main.js)
pnpm build && pnpm start         # in another terminal
pnpm exec playwright install chromium   # once; or set PW_CHROMIUM_PATH to an existing Chromium
pnpm test:e2e
```

It covers the homepage and navigation, sign-up/sign-in/sign-out and session restoration, guest
mode, onboarding validation and editing, the dashboard, week navigation and browser history,
journal/checklist/reminder persistence, consent withdrawal, data export, account deletion,
device sessions, not-found pages, robots/sitemap, and phone layouts without sideways
scrolling. Test accounts are created in whatever database the API uses.

## Pages

| Route | What it does |
| --- | --- |
| `/` | Homepage: hero, week previews, baby-this-week (from a published guide), features, timeline, latest articles, privacy |
| `/journey` | Trimesters and milestones, linking to every week |
| `/weeks`, `/weeks/[week]` | Baby development index and the public, server-rendered guide for each week (1–42); unpublished weeks are labelled |
| `/articles`, `/articles/[slug]` | Server-rendered article library with pagination; premium bodies unlock in the browser only for entitled accounts |
| `/signup`, `/login` | Email + password (Better Auth), "keep me signed in", TOTP step when 2FA is on, guest mode. Guest data moves into the account |
| `/onboarding` | Welcome → consent → dating method → dates → summary with the due date before saving → saved result |
| `/dashboard` | Greeting, current week, progress, next milestone, care guide, journal, checklist, reminders, next steps, new articles |
| `/timeline` | My pregnancy: any week's guide in tabs, previous/next, all weeks with dates, milestones |
| `/tools` | Daily plan: open tasks, quick actions, today's journal, reminders |
| `/journal`, `/checklist`, `/reminders` | Symptom log, preparation tasks with notes, reminders |
| `/settings` | Pregnancy details and due-date changes, profile, name, password, devices, 2FA, consent, export, deletion, membership |
| `/privacy`, `/terms`, `/contact`, `/goodbye` | Policy summaries, contact, deletion confirmation |
| `/admin` | Staff only: content workflow, checklist tasks, staff roles, audit log |

## Design

Tokens are in `src/app/globals.css` (cream `#FFF7F2`, rose `#D45D7A`, deep plum headings
`#512D46`, blush, sage, lavender), with a darker rose for white-on-rose text to keep 4.5:1
contrast, and a dark theme. Fonts: Fraunces (display) and Nunito Sans (body).

Illustrations in `public/assets/` are original SVGs generated by
`scripts/make-womb-illustrations.mjs` and `scripts/make-topic-illustrations.mjs`, plus the
hand-drawn `mother-hero.svg`. The four womb stages each cover a range of weeks and are not
medical depictions of a specific week. There is no photography: the API has no article images,
so article thumbnails are topic illustrations chosen from the title.

## How auth works

- **Accounts:** Better Auth session cookie set by the API; every request uses
  `credentials: "include"`. In production, serve the site and API from the same site
  (e.g. `app.example.com` + `api.example.com`) so the cookie is sent.
- **Guests:** `POST /v1/anonymous-sessions` returns a secret, kept in `localStorage` and sent
  as `Authorization: Anonymous <secret>`. The API checks that header before the cookie, so
  account calls pass `asAccount: true` in `src/lib/api.ts`.
- Signed-in pages are client-rendered and `noindex`; personal data is never in server HTML.

## Backend dependencies (not built, so not shown as working)

- **Article search, categories, images and reading time:** the articles API has none of these.
  Reading time is estimated from the body on the article page only.
- **Reminder delivery and notification settings:** reminders are saved but nothing sends them.
- **Password reset, email verification, email change:** off until an email provider is chosen.
- **Premium purchase:** entitlements are read from the API, but nothing sells a subscription.
- **Appointments:** there's no appointment model; the site shows the guide's visit advice instead.
- **Social sign-in:** disabled in the API, so there are no Google/Apple buttons.
- **Week guides:** only weeks with published guides have content (the seed covers weeks 6–16).
